# XPS Fitting Studio — scientific and software audit

Date: 2026-09-08. Baseline: `aba24c6914342883079171032f72c9af9e055912`.
Audit branch: `codex/scientific-code-audit-2026-09`.

## Decision

Preserve the current architecture while fixing the calculation and state-contract defects below. A wholesale rewrite is not justified by the evidence collected. Prioritize trustworthy fitting, consistent area/uncertainty reporting, and reproducible saved projects before visual redesign.

The baseline cannot yet be considered scientifically validated across its advertised workflows. This does **not** mean every existing fit is wrong: independent Gaussian, Lorentzian, zero-asymmetry DS, and a constructed Shirley integral case pass, as do noiseless Gaussian mixture recovery checks. Specific failing workflows and assumptions are identified below.

This is the audit/initial-validation checkpoint requested before major restructuring. No production application source has been changed. New files are audit scripts, this report, and synthetic evidence. Experimental originals were read only; their inventory and derived metrics are stored outside the Git repository. GitHub publication remains blocked by invalid local authentication; the branch exists locally only at this checkpoint.

## Scope and evidence standard

Reviewed `fitting.py`, the Flask routes and active parsers, the frontend fit/area/import/export/state paths, extracted JavaScript modules, autofit model/constraint/statistical paths, reference loading/provenance, existing tests, CI, and deployment documentation. Independent Astra reviewers examined scientific and application concerns; a lighter reviewer inventoried tests and reference provenance. Findings were reconciled against current code rather than copied from previous audits.

Evidence levels:

- **Reproduced:** executable synthetic or extracted-production-function example included in the audit scripts.
- **Inspected:** directly supported by current source, but not exercised end to end.
- **Scientific limitation:** an assumption requiring calibration or experimental context, not automatically a software bug.

This review does not prove arbitrary inputs or all algorithms correct. In particular, exact CasaXPS LA equivalence, every reference constant, instrument-specific VGD calibration, posterior probability calibration, and experimental chemical assignments are not certified. Private deployment settings, authentication/rate controls, and the actual live process commit were not verified. The checked-in deployment documentation describes a separate macOS gunicorn checkout behind Cloudflare Tunnel; neither that checkout nor its services was changed.

## Confirmed numerical and statistical findings

| ID / priority | Finding and consequence | Evidence / location |
|---|---|---|
| S01 / P1 | DS+G shifts the energy origin on even-length grids. A symmetric analytic Voigt with true center 0 is fit at **+0.0250626585 eV**, half a channel on the 400-point grid. Changing ROI parity can change reported binding energy. | Reproduced; `fitting.py:271–281`; `audit_science_benchmark.py`. Odd-grid oracle passes. |
| S02 / P1 | LA normalization switches at the nearest sample: a **2×10⁻⁸ eV** center change causes a **3.245% of amplitude** curve jump. This can disrupt optimization derivatives and covariance. | Reproduced; `fitting.py:750–756`; science benchmark. |
| S03 / P1 | LA zero-pads the fitting window before convolution. Cropping a grid while keeping sampling and parameters fixed changes the curve on common points by **15.335% of amplitude**. This is different from legitimate finite-window integration loss. | Reproduced; `fitting.py:714–738`; science benchmark. |
| S04 / P1 | Manual/API `area_ratio` links peak heights. For Gaussian widths 1 and 2, requested area ratio 0.5 yields actual ratio **1.0** when slave width is free. Standard frontend linked peaks normally lock equal widths; the defect applies when unequal widths/shapes are allowed. Autofit's special free-width correction does not protect this separate path. | Reproduced; `fitting.py:867–875`; science benchmark. |
| S05 / P1 | Peak-area errors ignore amplitude/width covariance and shape-parameter contributions. Gaussian example reports **15.888** instead of full-covariance **10.312**; fixing width removes the area error despite uncertain amplitude. | Reproduced; `fitting.py:1230–1239`; `audit_statistics_repro.py`. These are conditional statistical errors, not full model/background uncertainty. |
| S06 / P1 | Ordinary F-distribution probabilities are used to test added nonnegative peaks. Zero amplitude is a boundary null with unidentified center/width, invalidating the ordinary F-test assumptions. Additionally, disjoint bounds on a shared peak are incorrectly called nested and produce a nominal p-value near **2×10⁻⁹**. | Statistical validity supported by Protassov et al.; structural false nesting reproduced; `autofit/criteria.py:60–110`. |
| S07 / P2 | DS+G physical-width checks use a symmetric Voigt estimate independent of asymmetry. A tested curve with measured FWHM **2.920 eV** is estimated at **1.168 eV**, escaping a 2 eV check. | Reproduced; `autofit/engine.py:798–808`; statistics benchmark. |
| S08 / P1 | MCR automatic rank selection loses information through centering. Three identical spectra of rank 1 are labeled three states; a rank-2 constant-plus-varying mixture is selected as one state with **20.4% lack of fit**. Rank is not by itself proof of chemical species, but these noiseless linear algebra counterexamples invalidate the current automatic selection. | Reproduced; `autofit/methods/multivariate_mcr.py:140–152`; statistics benchmark. |
| S09 / P2 | The manual-method wrapper accepts empirical noise weights but silently ignores them, always using `run_fit`'s own weighting. Independent weighted amplitude solutions differ (12.026 / 12.154), but the wrapper returns 12.599 for both. | Reproduced; `autofit/methods/least_squares.py:34–60`; statistics benchmark. |
| S10 / P1 for accepted edge-case options | Bayesian `n_replicas=2` produces beta=[0,0.0001], omitting beta=1, so the last replica is near-prior rather than posterior. A two-sweep run retains one sample yet labels posterior weight reliable and intervals "ok" despite unavailable ESS. The normal UI minimum reduces exposure but does not validate backend options. | Reproduced; `autofit/methods/bayesian_exchange_mc.py:141–143,425–443,544–556`; statistics benchmark. |

The DS+G oracle uses SciPy's independent Faddeeva-based Voigt function, not a second copy of the application's FFT. The LA findings test mathematical continuity and convolution-window behavior and do not depend on a claim of exact CasaXPS equivalence.

## Independent recovery and sensitivity results

Gaussian and Lorentzian formula errors are below 4×10⁻¹⁵ intensity units in the selected cases. Zero-asymmetry DS agrees with Lorentzian. The constructed Shirley background agrees within 6×10⁻⁹ intensity units. Four noiseless two-Gaussian fits recover centers and finite-window areas within the benchmark tolerances at two overlaps and two starts. These are useful positive controls.

The separate 72-fit experiment uses independent Gaussian truth, a known integral background, three fixed Poisson-noise seeds, two windows, two initial guesses, and fixed/free width variants. It is a **small sensitivity study**, not calibrated confidence-interval coverage or a universal ranking of backgrounds.

| Background | Widths | Largest absolute component-area error across the tested windows/seeds/starts |
|---|---|---:|
| Known true background | Free | 9.49% |
| Known true background | Correctly fixed | 2.68% |
| Shirley estimated from data | Free | 23.30% |
| Shirley estimated from data | Correctly fixed | 9.98% |
| Linear (misspecified for this truth) | Free | 76.33% |
| Linear (misspecified for this truth) | Correctly fixed | 9.44% |

All 72 report solver success. The large linear-background errors demonstrate misspecification, not a bug in computing a straight line. The advantage of fixing widths here assumes the correct width is known; incorrect constraints can instead bias results. The proper product response is visible assumptions and sensitivity diagnostics, not automatic trust in a low residual or convergence flag.

## Experimental records: Runs 5–9 only

All 59 requested project/spectrum files are readable. They contain 1,143 spectrum records, **964 distinct raw-array pairs**, and 876 records carrying a saved fit. No nonuniform raw grids were found. This deduplication distinguishes saved variants from independent experimental observations.

553 records with a saved fitted curve lack a matching complete stored grid/background tuple under the audited schema. This can reflect legacy formats or partial persistence and is **not** evidence that the raw spectrum is corrupt. Only 276 records could be compared by reconstructing the current backend model on the saved grid with the saved background; 55 exceed 1% of peak-height discrepancy. Those comparisons include version, mapping, and state effects and do not establish which curve is scientifically preferable. Eight legacy `LA` peak labels require the frontend's alias migration before strict backend replay; the current Python reference loader does not perform that migration. The new experimental audit script applies the explicit LA/DSG alias migration to in-memory copies and rejects unknown shapes rather than silently substituting Gaussian.

The full local inventory includes input SHA-256 hashes, names, per-record issues, and reconstruction metrics. It is deliberately outside Git in `../xps-audit-evidence/experimental-consistency.json`. No experimental raw arrays were copied into new repository files or uploaded. The counts in this report are aggregate coverage information.

Before treating experimental refits as validation truth, pair selected examples with acquisition metadata and independently exported instrument energy/intensity arrays. Current VGD parsing uses a first-plausible energy-calibration heuristic, scan averaging/truncation assumptions, and a default 4.5 eV work function. These need instrument comparisons; this audit has not demonstrated that 4.5 eV is wrong for these files.

## Scientific assumptions and provenance

- Manual fitting uses observed intensity as Poisson variance, although its API accepts counts or CPS. Dwell/accumulation and processing metadata are needed to interpret reduced chi-square and uncertainties. Background subtraction, smoothing and averaging can introduce correlation or change variance. Do not indiscriminately replace the likelihood without knowing how intensities were acquired.
- Area covariance must include correlations and shape parameters. It remains conditional on the chosen model/background; a corrected covariance calculation will not quantify uncertainty in chemical assignments or energy referencing.
- Positive-alpha uncut DS has a nonintegrable full-domain tail. Report finite-window areas and the integration convention; do not describe them as unique total areas independent of the ROI.
- Nominal F-test probabilities for additional nonnegative components should be suppressed or replaced by a suitably calibrated simulation-based comparison. BIC/AIC variants are correlated diagnostics, not independent confirmations of a chemical state.
- Bayesian evidence and intervals need independent-chain and repeated-data calibration at normal settings. Some amplitude prior bounds depend on observed data; this empirical prior choice should be documented and included in prior sensitivity. A heuristic evidence-error proxy or an ESS threshold alone does not certify posterior reliability.
- Reference loading provides useful schema, relationship and checksum validation. Curated records include 21 transitions; machine-tier records include 79 transitions across 52 elements; legacy has 113 records labeled unverified. Internal `VERIFIED` tier labels do not constitute external scientific certification: some curated notes describe derived values or outstanding hand-verification.
- Machine provenance has 27 dual-extraction corroborated and 52 single-snapshot records. Source recovery often uses archived NIST pages. A checksum establishes artifact consistency, not authority of its scientific values.
- Frontend RSFs are hardcoded practical library values, including caveats for U/Th. They need a versioned per-entry provenance table and instrument-appropriate validation; listing Scofield as a source is insufficient to identify the correction/convention used for each value.
- Reference bridge process caching does not invalidate with all source/provenance edits. The served dataset and autofit bridge use partly separate loading paths. Tests should cover value/provenance alignment and refresh behavior.
- Repository guidance about UCl4, satellites, backgrounds and charge references is useful context, not a substitute for primary-source scientific justification.

## Remediation order and acceptance criteria

1. **Fit correctness and model identity:** fix A01–A05/A08; snapshot immutable fit inputs with originating tab/revision; reject nonconvergence; use one explicit lineshape contract. Turn the eight application probes into passing regressions and add browser coverage for tab switching, Batch Fit, and Find Peaks replacement.
2. **Numerical consistency:** repair S01–S04, harmonize frontend/backend convolution and integration, retain legacy shape identifiers through explicit migrations. Require independent Voigt/continuity/window tests and both even/odd, ascending/descending grids to pass. Replace existing numerical TODOs with enforced tests after fixes, without loosening tolerances to conceal errors.
3. **Inference and reporting:** fix S05–S08, validate sampler options, account for covariance and uncertain model choices, and make unreliable significance/intervals visibly unavailable. Add repeated-noise false-positive/coverage calibration before claiming probabilistic reliability.
4. **Persistence and reproducibility:** version a complete fit-result record including grid, background, parameters, constraints, uncertainty, method, acquisition units, software commit and fit-input hash. Test all supported save/load/export formats; keep old project readers.
5. **Architecture cleanup:** extract pure numerical/state/serialization modules from the 14,383-line frontend only after behavior is pinned. Avoid parallel independent implementations of the same physical model where feasible. Add bounded background jobs and validated import schemas.
6. **UI:** expose fit state (edited/fitting/converged/failed/stale), background/constraint assumptions, statistical versus model uncertainty, and reproducibility metadata. Improve layout after the correctness contracts are enforced.

This sequence changes the isolated development branch only. Publishing or deploying the app is outside this audit's scope.
