DIAGNOSIS TO VERIFY: the "asym-GL" (Asymmetric Gaussian-Lorentzian) lineshape
is implemented as two mathematically different functions.

  BACKEND  fitting.py::_asymmetric_gl
    piecewise, two constant widths: high-BE side uses fwhm*(1+asymmetry)

  FRONTEND templates/index.html::asymmGL
    fwhmEff = x < center ? fwhm : fwhm*(1 + alpha*|x-center|/fwhm)
    high-BE width grows linearly with distance, unbounded

Claimed consequence: the chart's red envelope comes from
state.fitResult.fittedY (backend output) while the blue individual peaks are
recomputed in JS via evalPeakArray (frontend formula), so the two disagree on
screen.

CLAIMED NUMERICAL EVIDENCE (from the student's saved project, U 4f peak with
fwhm=1.83 eV, asymmetry=0.59, 4 peaks total):
  stored fittedY vs BACKEND-formula sum + background : max diff =  120 counts
  stored fittedY vs FRONTEND-formula sum + background: max diff = 1763 counts
