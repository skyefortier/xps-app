Rounds 1-3 drifted into a different question — "is the anchor a genuine spectral feature?" — and three intensity-threshold answers each either rejected real anchors (raw span vs a background ramp; max signal vs a one-channel spike) or were fooled by synthetic data. That question is real but it is older than this unit and is NOT what this unit fixes: Auto-Fit run on a single-channel spike (run B r3 #2, amplitude 14.6) or on featureless data with background None (run B r3 #1, amplitude 5.77) produced a non-zero anchor and a charge correction before this branch and still does. Please judge this round against the scoped rule; list anything about "genuine feature" separately as OUT-OF-SCOPE observations, not as findings against the verdict.

THE RULE NOW (_autoFitGraphiteIsSupported(gPeak, json)): the anchor is ZERO — and the auto-fit is rejected and rolled back before any charge-correction input is touched — when its amplitude is not finite, or <= 0, or below 1e-4 of the largest |count| the server fitted (json.counts), or within 3 of its own standard errors of zero when the server gave one; also when the response carries no counts. Rationale for the scale: it is in the data (a collapsed model still has a "strongest component"), it is the data the server fitted (upload rounding), it does not vanish on a flat region or depend on the background choice, and a spike can only raise it by 1e-4 of the spike.
Dispositions: run A r3 #1 (3.1649e-5 on data uploaded as 10.01, manual background) -> rejected (test); run A r3 #2 (300 000-count spike rejecting a 10 342-count anchor) -> accepted (test); run B r3 #1 and #2 -> out of scope as stated (one explicit scope test). Rounds 1-2 reproductions remain tests (collapsed model; sub-rounding signal 6.18e-5 and 3.096e-5 on 10; steep ramp accepted). 70 committed Graphite models: amplitude / max|counts| 0.61-0.86, amplitude / stderr 12-200. 20 Node tests.
