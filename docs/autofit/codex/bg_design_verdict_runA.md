**Findings**

1. BLOCKER: S3 is not killed by `fitResult.bgIntensity = backendResult.background_y` alone. `_doSaveSpectrum()` recomputes JS background and residuals at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:8675), `exportResults()` does the same at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:9294), and publication export recomputes JS background beside backend `fittedY` at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:9350). The design must route all fit data products through frozen fitted arrays when a backend fit exists.

2. MAJOR: Q1’s local-fallback claim is basically true. `runFit()` computes JS `bgSubtracted` before the backend call and passes it to `runFitLocal()` on failure at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:6793) and [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:6874). Batch propagation also calls `runFitLocal()` directly at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:10447). Freezing the last backend background would keep one authority only while settings stay stale; it would not survive ROI, charge correction, background type, endpoint averaging, manual-anchor, or bg-window changes offline without lying or disabling fallback.

3. MAJOR: The S2 `lo, hi + 1` fix is correct for the backend’s exclusive slice contract, including `hi + 1 == len`, reversed input if min/max is done first, narrower bg windows, and the one-point bail to full ROI. But the design under-scopes callers: auto-fit has the same request construction at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:6686) and [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:6703). A frontend-only change leaves `autofit/parity.py` and committed battery fixtures untouched, but future parity helpers that simulate frontend requests need a clear old-vs-new convention.

4. MAJOR: S2 is not universal across all methods. It affects integral methods and `linear`, because `run_fit()` uses `x[i0]` and `x[i1-1]` at [fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1068). It does not affect `manual` when `manual_bg` is present, and does not affect `none`/`flat`, which ignore the window at [fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1043) and [fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1075). Ranking language should say “all backend-fit request paths for windowed background methods,” not all methods.

5. MAJOR: Removing `shirley-iter` is not safe as written. `computeBackground()` directly dereferences `document.getElementById('shirley-iter').value` at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:4378), and save/project serializers also directly read it at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:8650). Also, “converged result independent of the knob” is not yet true for `shirley_linear`: the JS implementation has no convergence check at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:4247), while the design deliberately defers scientific review.

6. MAJOR: Post-fit invalidation semantics conflict with backend authority. Background inputs call `_invalidateBgCache()`, which nulls `state.fitResult.bgIntensity` at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:4278). Since `updatePlot()` requires a valid `fitResult.bgIntensity` to enter the frozen-fit path at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:7947), editing bg settings after a fit can discard the authoritative background without clearing the whole fit. The design needs an explicit policy: freeze fitted results despite setting edits, or clear the entire fit.

7. MINOR: Backend `background_y` is the right authority and no consumer appears to need the JS-computed version for length. But `uploadToBackend()` rounds BE/counts before upload at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:5926), so exact consistency should use `backendResult.energy`, `backendResult.counts`, and `backendResult.background_y` together, not frontend full-precision `be` plus backend arrays.

8. MINOR: Missing scope: `/api/background` does not mirror `/api/fit`. It slices and returns only the window, has no swap/clamp/<2-point/full-ROI embedding, and treats `manual` as zeros at [fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1281). This is not a live caller today, but it contradicts the “same +1 if/when one exists” simplification.

9. MINOR: S3 is not display-only. Quantification areas are peak-only via `_peakArea()` at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:7076), so At% is mostly insulated. But R-factor computes from `bgSubtracted`/`bgIntensity` at [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:9824), and spec/TSV/publication exports compute and persist JS-derived background/residuals.

VERDICT: NO-GO — The design does not actually make fitted background authoritative across save/export/autofit paths and underspecifies compatibility for removing the iteration control.
