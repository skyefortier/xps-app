**Findings**

1. **BLOCKER** Q3/S3: `fitResult.bgIntensity = backendResult.background_y` does not “kill S3 by construction” unless the design also rewrites serializers/exports/figure export. `_doSaveSpectrum()` recomputes JS background and residuals from live ROI/UI ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:8673)); `exportResults()` does the same ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:9294)); `exportFigure()` also uses JS background with backend `fittedY` when lengths happen to match ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:9350)). Stack Path A is fine because it uses `fr.bgIntensity` when present ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:7467)).

2. **MAJOR** Q1: the central claim is mostly correct, but overstated. `runFitLocal()` requires caller-supplied `bgSubtracted`/`bgIntensity` and computes residuals against that client-side subtraction ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:6874), [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:6951)). You could “freeze last backend background” as one authority only for the same ROI/grid/bg settings; it fails as soon as the user changes ROI, bg-start/end, bg type, endpoint averaging, charge correction, or has no prior backend fit. So offline fallback needs a JS background authority for new offline states.

3. **MAJOR** Q2: frontend `(lo, hi + 1)` is the right fix for normal finite bg windows, including `hi + 1 == len`, reversed inputs, narrowed windows, and one-point windows because `run_fit()` clamps, swaps, and bails on `<2` slice points ([fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1006)). But the design must specify the finite-input guard: one blank/NaN endpoint currently makes JS preview fall back to full ROI, while a naive nearest-index `lo/hi+1` can send a partial window. Also Auto-Fit has its own `/api/fit` payload builder and must receive the same fix ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:6686)). A frontend-only change does leave `autofit/parity.py` and battery fixtures untouched because their exclusive slice contract remains unchanged ([autofit/parity.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/autofit/parity.py:69)).

4. **MAJOR** Q3: backend arrays are length-compatible, not bit-same with frontend arrays. `uploadToBackend()` rounds BE to 4 decimals and intensity to 2 decimals before `/api/upload` ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:5926)); backend `background_y`, `fitted_y`, and `counts` are therefore on that rounded session grid ([fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1265)). The design should store `fitResult.be = backendResult.energy` and `bgSubtracted = backendResult.counts - backendResult.background_y`, or make upload lossless enough that this distinction disappears.

5. **MAJOR** Q4: removing `shirley-iter` is not safe “because the converged result is independent of the knob” until all JS twins actually converge with Python semantics. Current JS `shirley` and `shirley_linear` are fixed-count loops with no tolerance ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:4027), [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:4247)); `smart_exp` has a tolerance but it is `1e-4`, not Python’s `1e-6` ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:4115)). DOM removal also requires updating `_captureUI()`, `_restoreUI()`, `_onBgTypeChange()`, save-fit metadata, and tests that assert `shirleyIter` round-trips.

6. **MAJOR** Q5: the harm ranking is partly contradicted. S2 is not universal across all methods: it affects integral backgrounds and `linear`, but `manual` with anchors ignores `bg_start_idx/bg_end_idx`, and `none` ignores them ([fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1043), [fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1073)). S3 is not purely display-only: `_computeRFactor()` computes from stored `bgSubtracted/bgIntensity/fittedY` ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:9824)), and `.spec.json`/TSV exports compute residual/background outputs from JS as noted above. Quantification areas are peak-only and do not depend on background.

7. **MAJOR** Q6: missing design item: `_invalidateBgCache()` currently nulls `state.fitResult.bgIntensity` on bg endpoint, endpoint avg, bg type, and charge-correction edits ([templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:4278), [templates/index.html](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/templates/index.html:4650)). That breaks the proposed frozen backend-authoritative display path by forcing `updatePlot()` out of `haveFit` and back to JS preview behavior.

8. **MINOR** Q6: `/api/background` is still semantically inconsistent with `/api/fit`: it slices directly without swap, full-ROI bail, flat-hold embedding, or manual-anchor support ([fitting.py](/Users/skyefortier/xps-app/.claude/worktrees/fix-lacx-docstring/fitting.py:1281)). There is no live frontend caller, but it is a documented endpoint and should either share `run_fit` background normalization or be explicitly narrowed/rejected.

VERDICT: NO-GO — the design’s authority boundary is incomplete because saved/exported fit artifacts, cache invalidation, auto-fit, and rounded backend grids can still mix JS backgrounds with backend fit results.
