CLAIM: the user types bg-start / bg-end. The on-screen preview
(computeBackgroundCore) used every grid point with lo <= BE <= hi. Both
/api/fit request builders (runFit, runAutoFitC1sGraphite) instead picked the
NEAREST grid index to each bound and the backend slices counts[i0:i1]
Python-end-exclusive, so the fitted background was anchored one point inside
the window the user drew. THE FIX: one helper `_bgWindowIndices(be, bgStart,
bgEnd)` (inside-range, inclusive at both ends; blank/NaN bound or < 2 points
in range -> full range) used by computeBackgroundCore AND both request
builders, which send end_idx = i1 + 1. Backend contract unchanged.
