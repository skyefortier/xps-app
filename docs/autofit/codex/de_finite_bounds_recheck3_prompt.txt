WHAT CHANGED, AND WHY
Every finding in rounds 2 and 3 came from the widening machinery added in round 1 (budget, tolerance bands, refits replacing incumbents). It has been REMOVED rather than patched again. Design now (git diff 35b950e..HEAD -- fitting.py):
- _finite_search_box closes open sides of freely varying parameters for differential_evolution only (amplitude +-reach, centre = ROI range, always a real interval) and returns {name: {side: scale}}.
- run_fit: DE first search, then the unchanged perturb loop. AFTER it, if the final solution lies within 1 % (side's own scale) of a generated side (_near_search_sides), _polish_outside_search_box refines it FROM that solution with method least_squares and the request's own open bounds. The polished result replaces the incumbent only if polished.success and polished.chisqr <= incumbent.chisqr * (1 + 1e-9); otherwise the incumbent is returned with success=False and a message naming the parameter(s). Nearness alone never refuses; no candidate is discarded for a worse one; there is no widening, no budget.
- Generated sides are never serialised as min/max.
