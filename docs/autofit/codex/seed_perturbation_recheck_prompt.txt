Documentation: BLAS attribution corrected (this machine's numpy/scipy use Apple Accelerate); numpy's Generator stream is not promised across versions (a failing pin after an upgrade is a release note); "identical request" defined (after a fit the page holds fitted values, so a second press is a different request; reloading a saved project and pressing Run Fit is the repeatable case); the seed is not an identity / cache key.
6. NEW, found while fixing the tests and stated plainly in CLAUDE.md and the test docstring: seeding is necessary but NOT sufficient for Trust-Region. The perturbed restarts start from the first Trust-Region solution, which jitters at ~1e-5 (BLAS dot-product rounding depends on memory alignment; scipy's trf amplifies it); near a basin boundary that is enough to send a restart into another minimum. On the synthetic five-component model in the tests two presses of the SEEDED request differed by 29 percentage points; on the 202 committed targets x 5 presses, re-measured with the final seed derivation, before -> after: Trust-Region byte-identical on 51 -> 145 targets, > 1 pp between presses on 8 -> 0, > 0.01 pp on 14 -> 2 (worst 0.30 pp); LM byte-identical on 145 -> 202. The Trust-Region tests therefore assert the seed and the draws exactly and deliberately nothing about the result. Tightening ftol/xtol/gtol to 1e-12 was measured on the same set and made it WORSE (123 byte-identical, two targets abort). Cures (reproducible-arithmetic BLAS; a deterministic perturbation base) are recorded as owner decisions, not attempted.
