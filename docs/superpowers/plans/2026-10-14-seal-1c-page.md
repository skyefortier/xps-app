## 1. The seal — one deep-frozen object per fit, tagged by engine

`fitResult.seal = deepFreeze({v: 'xps-seal-1', engine: 'server' | 'local', producer, R, O, D, E})`.
`producer`: 'runFit' | 'useSolution' | 'autoFit' (server) / 'local' | 'batch' (local).

**R (both engines) — what the fit was made from, captured synchronously before the first await:**
- `pageModel` — a deep copy of the peak objects the fit STARTED from, every own field (Run Fit: the
  live peaks; "Use this solution": `opts.startPeaks`; Auto-Fit: each fit's built model with its
  `_af*` overlays; Batch: the target's peaks after propagation and scaling);
- `context0` — ONE record of the context, every field as typed / held: the `_STARTS_UI_FIELDS`
  (bg type, bg start / end, Shirley iterations, endpoint averaging, ROI min / max), the fit-method
  selection, the charge-correction settings (method, reference, custom value) AND the shift in force
  (`ccShift`, required finite — a producer refuses a non-finite shift, since `_roiSelect` reads NaN
  as 0), the manual anchors, and the producer's settings (`n_perturb`, `n_starts`,
  `require_component`; local: the engine options);
- `idx` — the indices `_roiSelect(rawBE, rawIntensity, context0.ccShift, context0.roiMin/Max)`
  returned; `energies`, `counts` — the arrays the fit received (server: exactly what
  `uploadToBackend` sent; local: the corrected energies and raw intensities of `idx`);
- `page` — the producing page's identity: the `xps-software` and `xps-page` meta contents
  (`page_sha256`, `reference_sha256`).
- server only: `request` — the wire body exactly as sent, `session_id` removed (transport).
There is no separate `R.roi` / `R.ccShift`: both are read from `context0` (one source; review B1).

**O** — server: the `/api/fit` reply verbatim. Local (V6.7, §6.4): `{engine: 'local', energies, net,
background: {values, certificate, effect}` (ordinary fields, not array properties), `weights`,
`paramMap`, `model` (the frozen final snapshot), `curves`, `modelSum`, `chi2`, `chi2r`, `rmse`,
`rFactor`, `areas`, `iterations`, `certificate`, `support`, `success: true`, `reportable: false}`.

**D** — `{chosenAlternative}` ("Use this solution": the alternative's description, attributed
history); otherwise `{}`. Auto-Fit's finalisation is not a D step since Q8 (it refits).

**E** — Auto-Fit only: the anchor fit's `{R, O}` (same server schema), judged in §6.3.

## 2. One context binding (V6.4)

From `R.context0` alone the page derives, and requires EXACTLY:
1. `ccShift` finite; `_linkGraphFailure(R.pageModel)` null.
2. **Samples:** `_roiSelect(tab.rawBE, tab.rawIntensity, context0.ccShift, context0.roi*)` → `R.idx`
   element for element; `R.energies[j]` = that reader's corrected energy, `R.counts[j]` =
   `tab.rawIntensity[R.idx[j]]` (server: `O.energy` / `O.counts` = R's; the server checks too).
3. **Step 0:** `_buildFitRequest(producer, R.pageModel, context0, R.energies)` — the ONE pure builder
   the producer itself uses (`peakToBackendSpec`, the background payload through `_bgWindowIndices`,
   averaging as the request reads it, `context0`'s own anchors, the method, `n_perturb`, `n_starts`,
   Auto-Fit's overlays and `require_component`) — equals `R.request` exactly (key order irrelevant,
   values and presence exact: an omitted field is not an explicit null).
4. **Background:** the page's certified background for `R.energies` / `R.counts` under `context0`
   (`computeBackgroundCore`) equals `O.background_y` (server) / `O.background.values` (local)
   exactly, and `_bgEffect` of `context0` equals `O.background_verdict.effect` / `O.background.effect`.
5. **Display frame:** the chart's energies are `rawBE[R.idx[j]]` corrected by the LIVE shift, which
   the live binding (§3) requires equal to `context0.ccShift` — never a translation of R's energies.
A narrower `idx` paired with a wider `context0` fails 2; an inconsistent request fails 3.

## 3. The live binding

`_sealLiveKey()` is a canonical key of the LIVE peaks (every field `project` reads or writes, incl.
the `_af*` overlays) and the LIVE context (every `context0` field, through `_fitKeyCanon`'s readers —
integers by `parseInt`, energies by `parseFloat`). The binding holds when it equals
`_sealKeyOf(project(R.pageModel, O, D), R.context0)`. VISIBLE CHANGE: the method selection and the
charge-reference settings are now part of the fit's context — changing either after a fit makes it
stale (until today they were outside the key).

## 4. `project` — the live path as a pure function (V6.3)

`project(pageModel, O, D)` (server): a deep copy of `pageModel`; per component `_applyBackendParams`'
own rules as a pure function of (copy, O's params) — a locked field keeps the snapshot's value, a free
one takes O's through the live conversion, an expression takes O's whatever the lock (Q10 0c); no
mutable object shared with the seal. The live path becomes `applyInPlace(state.peaks,
project(...))` — ONE reading. Local: the projection is `O.model` (the frozen snapshot the engine
committed), with every held and linked field required equal to `pageModel`'s (§6.4).

## 5. States and their presentation (V6.5 as amended)

`sealedState(fr, owner)` → `{state, check, reason, view}`, the ONLY reader of R / O / D / E:
- **CURRENT** — §2 holds, §3 holds, (Auto-Fit) §6.3 holds, and the verification (§9) answered
  `consistent` for THIS seal (local: the page's own exact check, §6.4).
- **PENDING** — §2/§3 hold, the verification is outstanding.
- **UNCONFIRMED** — §2/§3 hold, the verification answered `unconfirmed` (other software record,
  non-finite, a non-bit-stable lineshape's evaluation) or the server could not be reached.
- **STALE** — §3 fails (an edit), or §2 / §6.3 fails, or the verification answered `mismatch`
  (the failed check named).
- **PEAKS-ONLY** — no usable seal (fails its schema), or a legacy fit the adapter cannot reconstruct.
- **LEGACY** — an UNSEALED fit (saved before this release): today's restore machinery decides what it
  can show; a permanent ceiling makes it never current (Q1): "saved before sealed records — re-run
  this fit to confirm" (1d).

| | CURRENT | PENDING | UNCONFIRMED | STALE | LEGACY / PEAKS-ONLY |
|---|---|---|---|---|---|
| header χ²ᵣ | value | value + "confirming…" (visible text, not a tooltip) | value + "unconfirmed: reason" | "— (model changed / check failed: …)" | as today + "saved before sealed records" |
| R panel | value + level | value, "confirming…", no level wording | value, "unconfirmed", no level wording | none | as today, qualified |
| σ / uncertainty rules | O's σ, rules | O's σ, rules, state note | same, state note | none | as today |
| support exclusions | O's verdicts | O's recorded verdicts applied (they describe the shown recorded fit), labelled recorded | same | none (nothing established) | as today's legacy rule |
| areas, Quantify | O's | O's, state note | O's, state note | live preview, "model changed" | as today |
| alternatives | listed; Preview, Use | listed; Preview; Use disabled "confirming…" | listed; Preview; Use disabled "unconfirmed" | "no longer applies" | counts only |
| certificate / starts / required / success | "as recorded — not proven" + Re-run (1d) | same | same | not shown | as today |
| exports (CSV/XLSX/TSV/PNG) | values, state CURRENT, record, provenance | values, state PENDING | values, state + reason | WARNING, no statistics / σ | as today + LEGACY note |
| saves | the seal | the seal (re-judged on load) | the seal | the seal + the edited workspace | legacy fields as today |

`_statsState` / `_statsLiveState` / `_statsRecordState` / `_startsIfCurrent` /
`_certificateMoveIfCurrent` / `_isUnsupported` / `_currentSupport` (a separate authority, review A2/B2)
become thin readers of `sealedState` (CURRENT → 'current', STALE → 'stale', PENDING / UNCONFIRMED /
LEGACY → their own states — never 'current'). `_refreshStatsState` compares `{state, check, reason,
seal identity}`, so PENDING → UNCONFIRMED repaints. The starts panel distinguishes "confirming…",
"unconfirmed: …" and "model changed".

## 6. Producers

**6.1 Run Fit.** `pageModel` and `context0` captured before the first await; the request built by
`_buildFitRequest` from them (the same function step 0 runs); `idx` / `energies` / `counts` from the
one `_roiSelect`. On reply: seal; install (PENDING); verify (§9).
**6.2 "Use this solution".** As 6.1 with `pageModel = opts.startPeaks` (the live pre-operation model
is kept only for the ownership check); `D.chosenAlternative`.
**6.3 Auto-Fit (V6.3 step 2, the transaction).** One operation spans both fits AND both
verifications; the progress overlay stays until the commit. Before the commit the page requires:
R₁ binds to the same tab's raw data under `R₁.context0` (§2); `/api/verify-fit {R₁, O₁}` →
consistent; `O₁.success === true`; the anchor gate (`_autoFitGraphiteIsSupported`), the
reference-centre window and `O₁.required` re-derived by the same functions from O₁; `derive(R₁, O₁)`
— the projection of O₁ onto `R₁.pageModel`, every centre and manual anchor moved by −Δ, the endpoint
fields re-rounded only when Δ ≠ 0, the overlays carried, the window reselected in the new frame,
every centre locked, the producer's settings unchanged — equals `(R₂.pageModel, R₂.context0)`
exactly; `/api/verify-fit {R₂, O₂}` → consistent, and O₂'s anchor still passes. COMMIT: charge
correction, model and seal (R₂, O₂, E = {R₁, O₁}) at once, one undo entry. ROLLBACK (still owner):
any failure, including a verification that is unconfirmed or unreachable — "Auto-Fit could not be
confirmed; nothing was changed" (visible change). SUPERSEDED: nothing written. On load, CURRENT
needs E judged the same way (two verifications).
**6.4 The local engine and Batch Fit.** `R` as §1 (no `request`); the engine options in `context0`.
`runFitLocal` finalises ONE frozen snapshot (0b) and returns O_local beside the committed peaks. The
page is its own verifier: re-evaluate `curves` and `modelSum` from `O.model` on `O.energies` with the
page evaluators, χ² / χ²ᵣ / RMSE / R / areas / support in the engine's own arithmetic — exact; bind
`O.paramMap` and every held and linked field of `O.model` to `R.pageModel` (a held value is the
start's, a link follows its parent); the background as §2.4. Batch: each target's R after
propagation and scaling, from that target's own raw arrays and context. The starting-point
designation (`_isLocalFit`, `reportable: false`) is unchanged.

## 8. Mutators, snapshots, persistence, provenance

**8.1 Mutators.** A sealed fitResult is `{seal, view}` and frozen; `_invalidateBgCache`,
`_invalidateFittedY`, `_restampSupport`, the lazy rFactor are no-ops on it (the edit preview reads
live peaks and the live background separately, as STALE shows). LEGACY / SEALED DISPATCH IS
STRUCTURAL: every loader and restore entry branches on `fr.seal` first; `_restoredFitBgFailure` and
the rest of the restore machinery throw if handed a sealed fit.
**8.2 Undo / history / Auto-Fit snapshots.** Peak-only undo keeps the installed seal and re-judges
(undoing an edit returns CURRENT). Contextual undo, history restore and Auto-Fit rollback reinstall
the CAPTURED seal reference and rebuild its view (verification cache reused, §9). A snapshot with no
seal restores no seal.
**8.3 Provenance (G6).** `view.provenance` = ATTESTED when `O.software` (server) or `R.page.software`
(local) has a 40-hex `git_commit`, `git_dirty === false`, an `env_sha256`, and `R.page` holds
`page_sha256` and `reference_sha256`; else INCOMPLETE with what is missing. A note, never
withholding statistics (Q4). Shown in Results, exported, saved.
**8.4 Saves.** Project: the tab's workspace (peaks, ui, anchors, cc) as today, plus `fitResult: {seal}`
— nothing else authoritative. Spectrum file: `seal` at top level; its convenience arrays (roiBE,
background, fittedY, residuals, peakCurves, statistics) are written FROM the view for external
readers and ignored by the sealed loader. A STALE save keeps the seal and the edited workspace and
reloads STALE. A LEGACY fit re-saves its legacy fields as today (no seal manufactured); `tab.provenance`
(V6.8: the record kept when the reconstruction falls back to peaks only) is saved and loaded and
shown when `fitResult` is null. `.fit.json`: parameters for other data, the record as
`modelProvenance`, support null — unchanged.
**8.5 Loaders.** ONE function for both formats: `seal` present → schema check (fails → PEAKS-ONLY
with the reason, never a legacy reconstruction) → install `{seal, view}` → PENDING → verify (§9);
the workspace loads as saved and §3 judges it. No seal → the legacy adapter.

## 9. The verification manager

`_verifySeal(seal, owner)`: a cache `WeakMap(seal → {softwareAtVerify, result})`; one in-flight attempt
per seal (`attemptId`). Triggered on: fresh install, load (EVERY tab holding a seal, active or not —
stack sources included), history / undo / rollback reinstall when not cached, and "check again" after
an unreachable server. It never claims a fit operation (`_claimFitOp` is not used: a load must not
cancel a running fit). A reply is attached only if `owner` (the tab OBJECT) still holds that SAME seal
and the attempt is the latest for it; otherwise discarded. Unreachable → UNCONFIRMED "server
unreachable" (retryable). The bindings (§2, §3) are re-evaluated at every read; the cache holds only
the server's answer. On any change of a seal's result: Results, header, R panel, sidebar badges,
Quantify, history list and the `_renderDataCache` of every stack entry whose source holds that seal
are refreshed. Auto-Fit's two verifications run inside its own operation (§6.3).

## 10. Visible changes (release-noted; each measured in §12 step 9 on the committed fits)

- χ² shown and exported is the server's; the page formed χ²ᵣ × max(1, n − 3·peaks), wrong with links
  or locks. RMSE and R are the server's.
- The chart, Results, sidebar, Quantify and every export read the fit's recorded curves, residuals
  and areas instead of re-evaluating them in the browser (sizes measured against main).
- A reloaded fit keeps its σ, the lmfit card and its scattered-starts alternatives (O persists).
- Every server fit shows PENDING ("confirming…") until the check returns; UNCONFIRMED offline or when
  the verifier's software record differs from the fit's (e.g. after a deploy that changed the code or
  environment), until re-run (1d). Support exclusions, σ and Quantify show the recorded values with
  the state; "Use this solution" waits for CURRENT.
- Auto-Fit commits only after both of its fits are confirmed; it rolls back if the check cannot
  confirm them.
- Changing the method selection or the charge-reference settings after a fit makes it stale.
- Saves before this release are never current again (Q1).
- Acceptance labelled "as recorded — not proven"; provenance ATTESTED / INCOMPLETE shown.
- Edit previews no longer clear the stored fit's arrays (the STALE preview is computed beside them).
- Larger saves (full O, alternatives, Auto-Fit evidence; 1b measures the size) and a changed spectrum
  file (a `seal` field).

## 11. Tests

Positive round trips per producer (browser): fit → save project (JSON and ZIP) and spectrum → reload
→ CURRENT; a stack built only from sources reaches CURRENT without activating them. NEGATIVE, each
failing its named check: a wrong-spectrum E; an R whose `idx` is narrower than its `context0`; a
request not rebuildable from `pageModel` / `context0`; a background differing by an ulp; a live edit /
method change → STALE; offline → UNCONFIRMED; a software record differing → UNCONFIRMED; stale
convenience arrays beside a valid seal (ignored); a local fit whose held value differs from its
start; a pending fit's support in exports (labelled); a late verification reply after a tab switch /
close / reload with a reused tab id (discarded); PENDING → UNCONFIRMED repaint; missing provenance
(INCOMPLETE). Step 0 and the bindings also as JS unit tests on extracted functions (every shape,
links, locks, overlays, "Use this solution"). The legacy census on the 121 committed fits (all LEGACY,
re-save preserving their evidence).
