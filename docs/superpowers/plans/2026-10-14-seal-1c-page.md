## 1. The seal (one frozen object per fit)

`fitResult.seal = Object.freeze({v: 'xps-seal-1', producer, R, O, D, E})`, deep-frozen:

- `producer`: 'runFit' | 'useSolution' | 'autoFit' | 'local' | 'batch'.
- `R` (V6.2): `request` — the wire body exactly as sent, `session_id` removed (transport);
  `energies`, `counts` — the uploaded arrays, full precision (exactly what `uploadToBackend` sent);
  `idx` — `_roiSelect`'s indices into the tab's raw arrays; `ccShift` — the shift the energies were
  formed with; `roi` — `{min, max}` as typed; `pageModel` — a deep copy of the peaks EXACTLY as the
  request was built from them (every own field); `context0` — every `_STARTS_UI_FIELDS` field as
  typed, the method selection, `n_perturb`, `n_starts`, `require_component`, the manual anchors, the
  charge-reference settings.
- `O`: the server's reply verbatim (the `/api/fit` body, from `_serverFitJob`'s record), or the local
  engine's O (§5).
- `D`: `{chosenAlternative}` — the only producer step the page adds (Run Fit / Use this solution:
  none; Auto-Fit: none since Q8).
- `E` (Auto-Fit only): the anchor fit's `{R, O}`, its gates re-derivable (V6.3 step 2).

## 2. The view: every fitResult field consumers read is DERIVED from the seal

`_fitResultFromSeal(seal)` builds the object every current consumer reads — `be` (O.energy),
`bgIntensity` (O.background_y), `bgSubtracted` (counts − background, the server's association),
`fittedY` (O.fitted_y), `chi` / `chiReduced` / `rmse` / `rFactor` (O.statistics — the page no longer
forms them), `backendResult` (O), `starts`, `certificateMove`, `record` (`_fitRecordFrom(O)`),
`chosenAlternative` (D), `roiRange`, `uploadFull: true`, and the local engine's labels — plus `seal`.
No producer writes those fields any other way; the view is rebuilt from the seal on install, load,
undo, history restore and tab switch (all share the frozen seal). The in-place mutators
(`_invalidateBgCache`, `_invalidateFittedY`, `_restampSupport`, the lazy rFactor) stop writing a sealed
view: a live edit is judged by the binding (§3), not by nulling fields.

## 3. The state: `sealedState(fr, live)` → current | pending | unconfirmed | stale | peaks-only

DISPLAY-CURRENT needs ALL of (V6.4, V6.5 as amended):
1. **Step 0** — the page rebuilds the wire request from `R.pageModel` + `R.context0` with its own
   builder (`peakToBackendSpec`, the background payload through `_bgWindowIndices`, the producer's
   overlays — Auto-Fit's `_af*` fields and `require_component`) and it equals `R.request` exactly.
2. **Samples** — `_roiSelect(tab.rawBE, tab.rawIntensity, R.ccShift, R.roi)` returns `R.idx` exactly;
   `R.energies[j]` is that reader's corrected energy and `R.counts[j]` the raw intensity.
3. **Live** — the live model and context equal `project(R.pageModel, O, D)` and `R.context0` through
   `_fitKeyCanon`'s readers (`_sameFitKey(_startsLiveKey(), keyOf(project(...), R.context0))`).
   `project` is the live apply path as a PURE function (§4).
4. **Background** — the page's certified background for R's inputs (`computeBackgroundCore` with
   `R.context0`'s settings and anchors) equals `O.background_y` exactly (measured bit-identical in
   1b; otherwise stale "background changed").
5. **Server** — `/api/verify-fit {R, O}` returned `consistent` for THIS frozen seal (a WeakMap from the
   seal to `{software, result}`); requested under the fit-operation token and the tab's ownership;
   a reply for another seal or a superseded operation is discarded.
States: CURRENT (all five); PENDING (1–4 hold, 5 outstanding — a fresh fit too: statistics shown
"confirming…"); UNCONFIRMED (1–4 hold, 5 answered `unconfirmed`, or the server is unreachable — shown
with the reason, never current); STALE (1–4 fail, or 5 answered `mismatch` — F1's stale rules, the
failed check named); PEAKS-ONLY (no usable R / O).
**Acceptance, option (b):** `O.success`, `O.certificate.certified`, a global method's `success`,
`O.background_verdict.converged`, `O.required` are shown AS RECORDED: the Results line reads
"Converged — as recorded by the fit, not re-proven here" with the Re-run control (1d) beside it.

`_statsState(fr, key)` and its callers (`_statsLiveState`, `_statsRecordState`, `_startsIfCurrent`,
`_certificateMoveIfCurrent`, `_isUnsupported`) are re-implemented on `sealedState`: CURRENT → 'current';
STALE → 'stale'; PENDING / UNCONFIRMED → 'unverified' with their own notes (values shown, never
current: no σ rule changes, exports write the state, saves keep the seal). So every F1 consumer
switches in the same release without a second reading.

## 4. `project(R.pageModel, O, D)` — the live path as a pure function

A deep copy of `R.pageModel`; `_applyBackendParams`' own rules per component as a function of
(copy, O's params) — locked keeps the snapshot value, free takes O's through the live conversion,
an expression takes O's whatever the lock (Q10 0c); `p._backendParams = O's params`. The live path
becomes `applyInPlace(state.peaks, project(...))`, so there is ONE reading. Support verdicts are
stamped from O on the projected model.

## 5. The local engine's O (V6.7)

`runFitLocal` returns, beside its committed peaks, `O_local = {engine: 'local', success: true,
energies, net, background (with certificate and effect), weights (the engine's own association),
paramMap, model (the frozen final snapshot), curves, modelSum, chi2, chi2r, rmse, rFactor, areas,
iterations, certificate, support, reportable: false}` — all from ONE frozen snapshot (0b). Its state:
the page is its own verifier (re-evaluate on the snapshot: exact), steps 1–4; acceptance its
certificate; the starting-point designation unchanged. Batch Fit seals each target the same way.

## 6. Saves and loaders

Project (`.proj.json` / `.proj.zip`) and spectrum (`.spec.json`): `fitResult: {seal}` — the seal
whole, full precision, nothing else authoritative (the view is rebuilt on load). `.fit.json`:
parameters for other data, never a seal (the record as `modelProvenance`, as today). ONE loader
function for both formats installs a seal (view + PENDING) and requests verification for the active
tab on load and for others on activation. UNSEALED saves go through the LEGACY ADAPTER: today's
restore machinery (`_restoredFitBgFailure` …) decides what is shown, and the state is never current
(Q1: "saved before sealed records — re-run to confirm"); the record, when present, is kept as
`tab.provenance` even when the reconstruction falls back to peaks only (V6.8).

## 7a. Visible changes (release-noted, measured in 1c on the committed fits)

- χ² shown and exported is the server's (`O.statistics.chi_square`); the page used to form
  χ²ᵣ × max(1, n − 3·peaks) — wrong whenever a peak is linked or locked. RMSE and R are the server's
  (`O.statistics.rmse`, `r_factor`; the page summed RMSE in another order — invisible at the shown
  precision).
- A reloaded fit keeps its σ and the lmfit card (O persists; `backendResult` used to be memory-only).
- Every fit shows PENDING ("confirming…") until the server's check returns — normally well under a
  second; offline, UNCONFIRMED.
- After ANY deploy, every earlier seal reads UNCONFIRMED "computed by different software" until it is
  re-run (1d) — the whole `software` record is compared (V6.5). Owner to confirm this is wanted.
- Saves made before this release are never current again (Q1): they load as today, with "saved
  before sealed records — re-run this fit to confirm".
- Acceptance is labelled "as recorded — not proven" (option (b)).
